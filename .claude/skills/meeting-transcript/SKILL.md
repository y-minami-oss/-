# 会議の文字起こし抽出（クライアント別）

Google カレンダー → Drive の文字起こしドキュメント → クライアント別ファイル →
そのままチャットに出す（SendUserFile で渡す）。

**方針: AI要約は作らない。話者名とタイムスタンプが付いた生の文字起こしをそのまま出す。**
要約が欲しいと明示された場合だけ、生データの後ろに追記する。

## 手順

### 1. 対象の会議を特定する

`mcp__Google_Calendar__list_events` を使う。
- 期間指定があればそれに従う。無ければ直近7日。
- `orderBy: "startTimeDesc"`, `timeZone: "Asia/Tokyo"`
- 結果が大きくてファイルに退避された場合は `jq` で絞る（下記）。

各イベントの `attachments[]` に議事録がぶら下がっている。タイトルで種別を判定する:

| 添付タイトル | 中身 |
|---|---|
| `... ～Transcript` | tldv の文字起こし（**生データそのもの**） |
| `... - Gemini によるメモ` | Google Meet の Gemini メモ。**前半が要約・後半に全文文字起こし** |
| `... ～Recording` | 録画（mp4）。文字起こしは取れないので対象外 |

**注意: 添付タイトルは途中で切れることがある。**
`【お打ち合わせ】イデアコンサルティング 企画打ち合わせ - 2026/08/` のように
末尾の `～Transcript` が落ちるため、タイトルの文字列一致だけで判定すると取りこぼす。
`fileUrl` が `docs.google.com/document/` のものは種別不明でも候補に含め、
中身の先頭（`# 文字起こし` / `# メモ` の見出し）で判定する。
`drive.google.com/file/` は録画なので除外してよい。

`fileUrl` から Drive のファイルIDを抜く:

```bash
# docs.google.com/document/ の添付を全部拾う(タイトルが切れていても取りこぼさない)
jq -r '
 .events[] | select(.attachments != null) | . as $e | .attachments[]
 | select(.fileUrl|test("docs.google.com/document/"))
 | [ ($e.start.dateTime // $e.start.date), $e.summary,
     (.title|if test("Transcript") then "TRANSCRIPT"
             elif test("Gemini") then "GEMINI" else "UNKNOWN" end),
     (.fileUrl|capture("/d/(?<id>[A-Za-z0-9_-]{20,})").id) ] | @tsv' "$F"
```

`UNKNOWN` は中身を読んで判定する。

### 2. クライアントを判定する

イベント名の規則:
- `【お打ち合わせ】<クライアント名>様` → **クライアント会議**（主対象）
- `<クライアント名>様　お打ち合わせ` → クライアント会議（旧表記）
- `【内M】...` / `1on1` / `【撮影】` / `【移動】` → **社内・撮影・移動。クライアント別には振らない**
  （`【内M】編集MTG（桜交通）` のように括弧内にクライアント名が入る場合は、
   社内会議として扱いつつ「参考」に分類してよい。勝手に各社チャンネルへ送ってはいけない）

クライアント名 → Slack チャンネルは `clients.tsv` を参照。
未登録のクライアントは `mcp__Slack__slack_search_channels` で
`#<番号>_<クライアント名>` を探し、見つかったら `clients.tsv` に追記する。

### 3. 文字起こしを取り出す

`mcp__Google_Drive__read_file_content` にファイルIDを渡す。

- `TRANSCRIPT` 種別 … 全体が文字起こし。そのまま使う。
- `GEMINI` 種別 … `# 文字起こし` という見出しから後ろが生の文字起こし。
  **その手前（概要・次のステップ・詳細）は Gemini の要約なので、生データが欲しい依頼では落とす。**
  ただし「次のステップ」は担当者付きToDoとして価値が高いので、
  要約も欲しいと言われた場合はここだけ拾う。

### 4. クライアント別に書き出す

`transcripts/<クライアント名>/<YYYY-MM-DD>_<会議名>.md` に保存する。

**ファイル名は「日付 + ASCIIのスラッグ」にする。** 例:

    transcripts/桜交通/2026-08-20_uchiawase.md
    transcripts/AOE/2026-08-21_kikaku-uchiawase.md

SendUserFile のパス処理は日本語ファイル名の一部の文字を落とすことがあり、
実際に `二藤様_お打ち合わせ.md` → `二藤样_...`、
`企画お打ち合わせ.md` → `企画打ち合わせ.md` と化けて
«does not exist» で渡せなくなった。どの文字が落ちるかは事前に判別できないので、
**ファイル名に日本語を使わない**のが唯一確実な回避策。
ディレクトリ名（クライアント名）は日本語で問題ない。
会議名の正式表記は本文のヘッダ（`# 【お打ち合わせ】〇〇様`）に書く。

よく使うスラッグ: `uchiawase`（お打ち合わせ）/ `kikaku-uchiawase`（企画お打ち合わせ）/
`geppou`（月次レポート）/ `henshu-mtg`（編集MTG）。
先頭にヘッダを付ける:

```markdown
# <会議名>
- 日時: 2026-08-20 13:00-14:00 JST
- カレンダー: <htmlLink>
- 出典: tldv 文字起こし / Gemini メモ（<Drive URL>）
- 抽出日: <today>

---

（ここから生の文字起こし）
```

同じ会議が複数の添付を持つ（Transcript が2つ等）場合は、時刻付きで両方保存する。

### 5. チャットに出す

**既定の渡し方はこのチャット。`SendUserFile` でクライアント別ファイルをそのまま渡す。**
クライアントごとに1ファイル（複数回の打ち合わせがあれば会議ごとに1ファイル）。
本人はそれを各クライアントのチャットや Claude Code セッションにそのまま持っていける。

チャットの返答本文には、どのクライアントの何日の会議を何件出したかの一覧だけ書く。
文字起こし本体を返答に貼り付けて埋めない（ファイルで渡す）。

Slack へ送るのは**明示的に指示された時だけ**。その場合も
`mcp__Slack__slack_send_message_draft` で下書きに留め、直接投稿しない。
送り先は既定で社内チャンネル（`clients.tsv` の2列目）。
`#ext_...`（クライアントと共有しているチャンネル）は、生の文字起こしに社内の率直な発言や
他社名が混ざるため、その回ごとに明示指示された時以外は使わない。

## 注意

- **添付があっても実体が消えていることがある。** カレンダーにドキュメントの添付が
  残っていても `read_file_content` が «Requested entity was not found» を返す場合がある
  （作成者が削除した／共有されていない）。`search_files` で同名を探して無ければ
  そこで止めて、**取得できなかった会議として明示的に報告する**。黙って飛ばさない。
- **クライアントが退出した後も録画が続いていることがある。** 文字起こしの末尾が
  社内メンバーだけの率直な会話（契約継続の見込み、他社ベンダーの評価など）に
  なっている回がある。その場合はファイル冒頭に取り扱い注意を書き、
  本文中でも区切りを入れて社内会話であることを分かるようにする。

- 文字起こしは音声認識なので誤字がある（社名・人名が特に崩れる）。直さずそのまま出す。
  勝手に補正すると発言内容が変わってしまう。
- 参加者に社外の人が含まれる会議の内容を、別のクライアントのチャンネルに置かない。
- 同名の会議が繰り返し予定の場合、日付でファイルを分ける。
