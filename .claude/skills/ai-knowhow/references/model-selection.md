# モデル選定とコスト

> ⚠️ **この表の数値はNotion DB(2026年6月収集)の転記で、実測していない。**
> 価格・スコア・モデル名は変動が速い。対外資料に載せる前に一次情報を確認すること。
> 特にモデル名は「そのモデルが本当に存在するか」を提供元のドキュメントで確認する。

## タスク → 推奨モデル

| タスク | 推奨 | メモ |
|---|---|---|
| 長時間自律コーディング / 大規模移行 | Claude Opus 4.8 | 欠陥見逃しが少ない |
| コスト重視のエージェント / 高速 | Gemini 3.5 Flash | フラッグシップ級を安く高速に |
| 日常アシスタント / 汎用 | GPT-5.5 Instant | 高速・低幻覚 |
| 自社ホストでコーディングを安く | GLM-5.2 / DeepSeek-V4(オープン) | 近い性能を大幅に安く |
| スマホ / オフライン / ゼロコスト | Gemma 4 E2B/E4B(ローカル) | 4bit量子化で約5GB RAM |
| Mac でローカル実行 | Ollama + MLX バックエンド | Apple Silicon で実用速度 |

## コスト原則(選定より効く順)

1. **プロンプトキャッシュ** — 入力コストを最大90%削減。システムプロンプトや
   共通の参照資料はキャッシュ対象にする。
   このリポジトリでは `src/extract_receipt.py` が既にシステムプロンプトを
   `cache_control` 対象にしている。
2. **ルーティング** — 全部を最上位モデルに投げない。タスクの難度で振り分ける。
3. **モデル選定** — 上の表。

推論価格は下落が続いている(年数十倍ペースという分析がある)。
**「安くなるまで待つ」より今使い始めて学習曲線で先行するほうが有利**、という判断が
DB の結論。ただし下落率の具体的な数字は出典依存なので、そのまま引用しない。

## このコードベースでの実際の設定

`src/extract_receipt.py` の `MODEL` 定数が領収書読み取りのモデルを決めている。
変更するときは、そのモデルIDが実在してVisionとPDFに対応しているかを
提供元のドキュメントで確認してから変える(存在しないIDを書くと実行時まで気づけない)。
