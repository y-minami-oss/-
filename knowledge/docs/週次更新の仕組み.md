# 週次更新の仕組み

毎週日曜に、新しい会議ログを取り込んでナレッジベースとGoogleドキュメントを更新する。

## 全体の流れ

```
日曜 22:00 (JST)   Claude の Routine が起動
                   ├ Drive の Meet Recordings から直近7日分の新規議事録を探す
                   ├ 読み込んで、ノウハウを抽出する
                   ├ docs/匿名ラベル一覧.md に従って匿名化する
                   ├ notes/ に追記する
                   ├ tools/build_doc.py と build.py を実行して成果物を作り直す
                   └ ブランチに push する
                        │
日曜 23:00 (JST)   Googleドキュメント側の Apps Script が起動
                   ├ GitHub から docs/google_doc_body.json を取得
                   └ ドキュメント本文を丸ごと書き換える
```

Googleドキュメントの本文を直接書き換えるAPIがコネクタ側に無いため、
**書き込みはドキュメント側のApps Scriptに担当させている。**
Claude はリポジトリに push するところまでを受け持つ。

## セットアップ（初回だけ）

### 1. Googleドキュメント側

1. 対象のドキュメントを開く
2. 拡張機能 → Apps Script
3. `tools/sync_doc.gs` の中身をすべて貼り付けて保存
4. **リポジトリを非公開にした場合**は、GitHubで fine-grained personal access token を発行し
   （対象リポジトリは `y-minami-oss/-` のみ、権限は Contents = Read-only）、
   Apps Script の `setToken` に貼って1回だけ実行する。実行後は貼った文字列を消して保存し直す。
   トークンはスクリプトプロパティに保存され、コードには残らない。
5. 関数 `syncNow` を選んで実行（初回だけ権限の承認を求められる）
   → この時点でドキュメントに本文が入る
6. 関数 `installWeeklyTrigger` を実行
   → 毎週日曜23:00（JST）に自動更新されるようになる

**注意：実行のたびに本文は全置換される。**
ドキュメントに直接書いたメモは消えるので、残したい場合はコメント機能を使うこと。

### 2. Claude 側

Routine「社内ノウハウ抽出（週次）」が設定済み（毎週日曜22:00 JST）。
claude.ai の Routines 画面、または `/routines` から確認・停止できる。

**⚠️ 1点だけ手動の作業が要る。**
このRoutineはツール経由で作ったため、**Google Driveコネクタが紐づいていない**。
このままでは議事録を読めないので、初回だけ次の操作をすること。

1. claude.ai → Routines → 「社内ノウハウ抽出（週次）」を開く
2. コネクタの設定で **Google Drive** を有効にする

有効になっていない状態で実行されると、Routineは何もせず
「Google Driveコネクタが紐づいていないため議事録を読めませんでした」とだけ報告して終わる
（推測で中身を書くことはない）。

## 追記のルール

- **匿名化**：`docs/匿名ラベル一覧.md` を必ず先に読み、既存ラベルを再利用する。
  新規クライアントは「業種＋未使用のアルファベット＋社」で命名し、一覧に行を足す。
- **実名・実額は書かない**：クライアント名、個人名、原価、契約単価、入金状況。
  実額に触れる必要があるときは「標準単価P」に対する倍率で書く。
- **リスキリング／助成金・補助金は Googleドキュメントに載せない**。
  `tools/build_doc.py` が該当する節と行を自動で除外する。notes/ には残してよい。
- **四半期ごとにファイルを分ける**：`notes/NN_実録_商談と定例_2026-09_10.md` のように。
- **★の付け方**：★＝参考になる／★★＝再現性がある／★★★＝そのまま型として使える。

## 手で動かすとき

```bash
cd knowledge
python3 tools/build_doc.py $(date +%F)   # docs/google_doc_body.{json,md} を作り直す
cp work/google_doc_body.json work/google_doc_body.md docs/
python3 build.py                          # knowledge-base.html を作り直す
```

## うまく動かないとき

| 症状 | 見るところ |
|---|---|
| ドキュメントが更新されない | Apps Script の「実行数」画面でエラーを確認。`SOURCE_URL` のブランチ名が正しいか |
| HTTP 404 | ブランチをマージ・削除した場合は `sync_doc.gs` の `SOURCE_URL` を新しいブランチ（main など）に書き換える |
| 実行時間の超過 | 段落数が増えすぎている。`tools/build_doc.py` で実録の索引以外を削るか、章を分割する |
| 同じクライアントに別ラベルが付いた | `docs/匿名ラベル一覧.md` の「既知の統合履歴」に倣って統一し、一覧を更新する |
