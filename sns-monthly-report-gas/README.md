# SNS月次レポート 自動集計（Google Apps Script）

毎月の定例作業を仕組み化するための GAS 一式です。各クライアントの **効果測定シート（投稿単位の生データ）** から対象月の実績を自動集計し、コントロール用スプレッドシートの **「集約」タブ** に「1行＝1社」で書き出します。

## これで自動化される範囲（Phase 1）

- ✅ 各社の効果測定シートを読み、**対象月の実績を集計**
  - 投稿数 / 再生数合計 / 再生平均 / EG率（＝(いいね+コメント+シェア+保存)÷再生） / フォロワー増加 / プロフ閲覧計
- ✅ **アカウントハンドル照合**：対象月の投稿URLが設定のアカウントと違うと警告（例：出光シートに山謙タブが混入していた事故を自動検知）
- ✅ **データなし判定**：対象月に投稿が無い社は「計測対象外/投稿前の可能性」と明記
- ✅ 設定シートに行を足すだけで**全クライアントに拡張可能**

## まだ手動 or 要calibration（Phase 2）

- 各クライアントの **プロジェクトシート（PROJECT DRIVE SHEET）への直接転記**と、
  **新月ブロックの追加**は、社ごとに月列・KPI行のセル位置が異なるため Phase 2 で対応。
  Phase 1 の「集約」タブの値を見ながら手入力 → もしくはセル位置を設定後に自動転記化します。

---

## セットアップ手順（初回のみ）

1. **コントロール用スプレッドシートを作成**（任意の名前。例：`SNS月次レポート_自動化`）。
2. そのスプレッドシートで `拡張機能 > Apps Script` を開く。
3. エディタに **`コード.gs` の中身を貼り付け**て保存。
4. コントロールSSに **`設定` という名前のタブ**を作り、`設定_seed.csv` の内容を貼り付け（A1から）。
   - 列：`有効 / クライアント名 / 効果測定シートID / 生データタブ名 / プロジェクトシートID / アカウント`
   - `生データタブ名` は空欄でOK（ヘッダーから自動検出します）。
   - `アカウント` は `@` 無しのハンドル（照合用。空欄なら照合スキップ）。
5. シート上部メニューに **「SNS月次集計」** が出る（出ない場合は一度リロード）。

> 権限：初回実行時に「このスクリプトに各スプレッドシートへのアクセスを許可」を求められます（あなたのアカウント権限で動作）。

## 毎月の運用手順

1. コントロールSSを開く。
2. メニュー **「SNS月次集計」→「前月を集計」**（または「対象月を指定して集計」で `2026-05` のように入力）。
3. **「集約」タブ**に全社の対象月実績が出力される。
   - `警告` 列に⚠が出た社は、効果測定シートのタブ混入・別アカウント混在の疑い → 要確認。
   - `状態` が「対象月の投稿なし」の社は計測対象外。
4. 「集約」タブの数値を、各プロジェクトシートの当月「結果」欄へ反映（Phase 2 で自動化予定）。

## 設定シートの運用メモ

- クライアントを増やすとき：`設定` タブに1行追加（`有効=TRUE`、効果測定シートID、アカウント）。
- 一時停止/未計測の社：`有効` を `FALSE` に。
- **出光リテール販売**：実数は外部「簡単DC」側にあり、効果測定シート(222)には山謙タブが混入。
  そのため初期は `有効=FALSE`。簡単DCのデータが効果測定シートに取り込まれたら、
  `生データタブ名` にそのタブ名を指定し `有効=TRUE` に。
- **さくらフォレスト / しろくま電力**：現状その月の生データが無いため `有効=FALSE`。

## 既知の注意点

- 集計対象は「投稿単位の生データタブ」。集計ブロック（`#REF!`になりがち）は使いません。
- 効果測定シートのヘッダー表記ゆれは `コード.gs` の `HEADER_ALIASES` で吸収。新しい表記が出たら追記。
- 投稿日が `2026/05`（スラッシュ）形式・Date型・文字列いずれにも対応。
- EG率の定義はチーム標準に合わせて調整可（現状は対再生のエンゲージ率）。
