## 共通の運用ルール

1. **「お試し → 本番」の二段構え。** 無料枠のあるモデルで構図・演出を検証し、
   本番の仕上げだけ高品質モデルに回す。最初から高いモデルを使わない。
2. **商用はライセンスと透かしを必ず確認**(`design-checklists.md` の B を回す)。
3. **画像で絵コンテを固めてから動画化**すると当たりが上がる。

## プロンプトの型

画像は「被写体 / 構図・アングル / ライティング / スタイル / 文字 / 比率」を分けて指定する。
動画は「シーン / 被写体の動き / カメラワーク / ライティング / 音 / 尺・比率」を分ける。

### 商品カット(EC/広告)
```
{商品}のプロダクト写真。被写体: {商品の素材・色}。
構図: 斜め45度・余白多め。ライティング: 柔らかい自然光、影は薄く。
背景: {色/シーン}。質感: フォトリアル、4K。比率 1:1。
```

### SNSサムネ(文字入り)
```
YouTubeサムネを作成。テキスト「{キャッチ}」を大きく中央に、可読性最優先。
背景: {テーマ}を想起させるビジュアル。配色: {ブランド色}。
比率 16:9、文字は崩さず正確に。
```

### 一貫キャラ(参照画像あり)
```
添付の人物を主役に、{シーン}のシーンを生成。
顔・髪・服装は参照画像と完全に一致させる。表情: {感情}。比率 9:16。
```

### 商品プロモ動画(シネマティック)
```
シーン: {商品}が{環境}に置かれている。
カメラ: スローなドリーイン→商品にクロースアップ。
ライティング: 映画的・柔らかい逆光。動き: 微風で表面がゆらめく。
音: 静かな環境音。尺8秒、比率9:16。
```

### 語り・トークカット
```
{人物}がカメラ目線で{テーマ}を話す。
口の動きはセリフ「{台詞}」にリップシンク。表情: {感情}。
カメラ: 胸元アップ・固定。背景: {場所}。尺10秒。
```

### 始点 → 終点の遷移
```
開始フレーム: {画像Aの説明}、終了フレーム: {画像Bの説明}。
両者を滑らかにつなぐカメラワークを生成。尺5秒。
```

## SNS商品プロモ動画の量産(所要 約10分/本)

1. 素材準備: 商品URL または 商品写真1枚。
2. フォーマット選択: cinematic / energetic / minimalist から1つ。
3. 生成: 各SNSのアスペクト比に自動最適化。
4. **1変数テスト**: フック / オファー / 声 / ビジュアルのうち **1バッチ = 1変数だけ**変える。
   ここが効く核心。複数を同時に変えると何が効いたか分からなくなる。
5. 後処理: フリッカー除去・色補正 + アップスケール。
6. 配信: 縦型カットに字幕/トリミング。

**勝負は予算ではなくクリエイティブの回転速度**、というのが DB の結論。
「フォーマットを1つに固定し、10プロンプトでバリエを作って2週間毎日投稿」という
運用設計のほうが、個々のプロンプト品質より効くとされる。

> ⚠️ 「UGC風広告はCTR約4倍・CV率約29%向上」等の数値は出典元の主張であり、
> 自社で再現した数字ではない。自分の案件で計測して置き換えること。

## 一貫キャラUGCの量産(顔が毎回変わる問題)

1. 顔を数分学習させてキャラをロック(Higgsfield Soul ID 等)。
2. 参照画像の再アップや顔特徴の再記述なしに、同一人物の複数アングルを生成。
3. 必要に応じて動画化。

人物一貫性が保てると、A/Bテストの変数をクリエイティブ側だけに絞れる。

## 提案スライド作成フロー

1. **リサーチ込み初稿**: Felo Slides(日本語・検索連動)。
2. **高ステークス資料の構成詰め**: Genspark Guide Mode(目的・聴衆・構成を対話で確定)。
3. **デザイン適用・画像生成**: Gamma、または社内スキル `s-base1-trepro` / `s-base2-trepro`。
4. **部分修正**: クリックした箇所だけ再生成(Genspark Mark and Edit)。
5. **展開**: 多言語・PDF・要約メールに変換。

使い分け: リサーチ込み初稿 = Felo / 失敗できない高ステークス = Genspark /
ブランド量産 = 社内スキル。

> ⚠️ DB は `ai-video-studio` `higgsfield-promo-video` `image-studio` `s-brand-slide`
> `deep-research` `schedule` という社内スキルを参照しているが、
> **この環境に実在するのは `s-base1-trepro` / `s-base2-trepro` /
> `nanobanana-slide-generator-v3-flash` のみ**。DB側の記述を実在するスキル名に直す必要がある。
