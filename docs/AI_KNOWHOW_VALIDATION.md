## 3. 検証で見つかった問題

### 3-1. ⚠️ 自走5手順に、公式にある重要な但し書きが2つ欠けている

**(a) plan mode を無条件に適用する書き方になっている**

公式ドキュメントは明確に留保をつけている:

> Plan mode is useful, but also adds overhead. For tasks where the scope is clear
> and the fix is small (like fixing a typo, adding a log line, or renaming a
> variable) ask Claude to do it directly. **If you could describe the diff in one
> sentence, skip the plan.**

DBの手順②は「plan modeで計画を出させ、実装と分離してレビュー」と無条件。
小さな修正まで plan mode に通すとオーバーヘッドだけが増える。
→ **「差分を1文で説明できるなら計画は飛ばす」を判断基準として追記した。**

**(b) 敵対レビューの副作用が書かれていない**

> A reviewer prompted to find gaps will usually report some, even when the work is
> sound, because that is what it was asked to do. Chasing every finding leads to
> over-engineering.

DBの手順④は「敵対レビューsubagentを挟む」だけ。全指摘を追うと過剰設計になる。
→ **「正しさか明示要件に影響する不備だけ挙げろ」と指示する旨を追記した。**

### 3-2. ⚠️ 公式にある新しい機構がDBに載っていない

自走の「止め方」には強度の異なる3段階があるが、DBはプロンプト内指示しか触れていない:

| 手段 | DBに記載 |
|---|---|
| プロンプト内で検証を指示 | あり |
| `/goal` 条件(別の評価器が毎ターン再チェック) | **なし** |
| Stop hook(通るまでターン終了をブロック) | **なし** |

他に `/rewind`(チェックポイント復元)、`/btw`(文脈を汚さない質問)、
agent teams も未収録。DB収集は2026年6月時点なので、この差分は更新で埋まる。

### 3-3. ~~⚠️ モデル選定早見表のモデルIDは実在確認が必須~~ → **取り下げ(誤検出)**

**当初この指摘を挙げたが、公式のモデル表と照合した結果、誤りだった。**

`src/extract_receipt.py` の `MODEL = "claude-opus-4-8"` は**実在する正規のモデルID**
(Claude Opus 4.8 / 1M文脈 / $5.00・$25.00 per 1M)。リポジトリは壊れていない。

「モデルIDは提供元のドキュメントで実在確認してから書く」という原則自体は有効だが、
このリポジトリに対する指摘としては成立しなかった。

公式の既定方針は「明示されない限り `claude-opus-5` を使う」なので更新の余地はあるが、必須ではない。
移行する場合の注意: **Opus 5 は thinking が既定でオン**(4.8 は既定オフ)なので、
領収書読み取りのような単純な抽出ではコストとレイテンシが上がる。`output_config={"effort": "low"}` を添える。

### 3-3b. `output_format` は非推奨ではなかった(こちらも訂正)

`output_format` が非推奨なのは `messages.create()` の場合だけ。
`client.messages.parse(..., output_format=PydanticModel)` は**現行の推奨API**。
`src/extract_receipt.py` の書き方は正しく、修正不要。

DB内のノウハウが「関連スキル」として挙げているもののうち、実在を確認した結果:

## 4. 検証のために実際に実行したこと

ノウハウ③「検証手段を必ず与えてから実装させる」を、このリポジトリ自身に適用した。

### 4-1. テストの実行(証拠)

初回実行は失敗した:

```
$ python3 -m unittest tests.test_logic -v
ImportError: Failed to import test module: test_logic
ModuleNotFoundError: No module named 'anthropic'
```

原因は依存の未インストール(READMEの手順自体は正しい)。インストール後:

```
$ python3 -m pip install -r requirements.txt && python3 -m unittest tests.test_logic
Ran 12 tests in 0.005s

OK
```

12件すべて PASS。**テストは壊れていない。**

### 4-2. 見つかった本当の問題と、その修正

依存が入っていない状態では、**Claude Code on the web のセッションは毎回
「検証手段ゼロ」から始まる。** これはノウハウ③が指摘する状態そのもの
(「検証できる手段がないタスクは、まず検証方法を作るところから始める」)。

対処として SessionStart hook を追加した:

- `.claude/hooks/session-start.sh` — web セッションで `requirements.txt` を install
- `.claude/settings.json` — hook を登録

検証結果:

| 確認項目 | 結果 |
|---|---|
| hook 実行(remote) | ✅ exit 0、出力なし |
| hook 実行後のテスト | ✅ 12件 PASS |
| web以外での no-op(`CLAUDE_CODE_REMOTE` 未設定) | ✅ 何もせず exit 0 |
| 冪等性(複数回実行) | ✅ 問題なし |
| `settings.json` のJSON妥当性 | ✅ valid |

playwright のブラウザ本体はダウンロードしない。TeamSpirit は社内ログインが必要で
クラウドから操作しない方針であり、テストにも不要なため。
